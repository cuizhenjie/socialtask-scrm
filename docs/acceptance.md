## 推荐执行命令

```bash
# 源码验证（当前交付环境已执行）
bash scripts/check-domain.sh
node scripts/check-syntax.cjs
python scripts/check-contract.py

# Maven/MySQL 真实集成（当前交付环境未执行）
cd services/api
mvn -B -ntp test

# Next 实际构建（当前交付环境未执行）
cd ../../apps/web
npm install
npm run typecheck
npm run build

# 服务联调（当前交付环境未执行）
docker compose --env-file infra/.env -f infra/compose.yaml up -d --build
curl -fsS http://127.0.0.1:8080/actuator/health
```

**最小验收门槛：** A01–A22、A24–A29 必须全部经过真实环境执行与证据记录，A23 在企业微信开通对应授权前不宣称完成。A30 属业务合规上线前必过项。任何不能覆盖的内容需记录负责人、原因、回滚方案和手工替代路线。


## 当前验收入口

- `make test`：构建真实 Next.js standalone，执行隔离 PostgreSQL 引擎、PostgREST/Storage HTTP 模拟和业务调用。包括首管理员、权限、回调幂等、关联工单、执行人素材下载、回传审核、调度以及附件/消息保留。
- `scripts/full-business-e2e.py`：是额外的桌面与移动浏览器验收，须显式设置 `QA_CONFIRM_DISPOSABLE=YES`、`QA_WEB_URL`、`QA_DATA_API_URL`、`QA_SERVICE_ROLE_KEY` 和临时管理员参数。应用和 Data API 都必须是隔离、仅回环监听的测试实例。不要在真实用户或生产库运行。
- 实际方舟工作区和企微真机另验。上线前校验现有附件迁移、新建附件与重启后的回读、提醒和外部通知，入口见 [部署](RELEASE.md)。
