## v1.1 验收追加：工单 SLA、标签、报表及企微双向消息

> 以下是**待实际执行**的验收用例，不能将清单写成实测通过。

1. MySQL 8.4 空库执行 Flyway V1、V2，不出现重复建表或外键错误；升级已有 V1 库时不丢失任务/客户/审计/通知记录。
2. 现有工单的 SLA 快照回填：首次响应以最早任务提交记录为准，解决以最终任务更新时刻近似回填；历史违约记录不能被重算覆盖。
3. 创建 7×24 策略，响应/解决 SLA 分别正确计算；创建工作时段策略，周五 17:30 加 120 分钟应落在下周一 10:30（亚洲/上海，周一至五 09:00–18:00）。
4. 管理员修改 SLA 模板后，旧任务已有快照不变；新创建任务使用新模板。已提交/已违约工单不能通过优先级变化清除违约。
5. SLA 提前预警、违约在到期窗口内只产生一条事件；在管理员消息中心可查询且不会假装企业微信已发送。
6. 新建分组/标签、分配人员标签、按角色/分组/标签检索；停用成员不再进入可派单名单。
7. 创建普通工单、下发、执行人提交 notes、管理员审核，SLA 响应与解决时间都持久化。
8. 按日期、分组、标签、类型、状态查询报表；完成/待审核/SLA 违约与明细一致；非管理员访问报表返回 403。
9. 企业微信 `GET /api/v1/wecom/callback`：正确签名与企业 ID 通过，篡改签名或错误企业 ID 失败。
10. 企业微信 `POST` 加密回调：相同 MsgId 重试两次只写入一条，人员 UserID 能匹配内部人员，未匹配不会冒充客户。
11. 企业微信消息卡片在真实自建应用中点击后访问正确 `/m/tasks/{id}`；成员身份与可见范围、会话登录、过期链接均现场验证。
12. 未配置应用凭据时出站通知显示 `NOT_CONFIGURED`，管理员可在配置后重试；平台返回无效成员必须记录为失败。
13. `SENT` 只表示平台 API 接受消息，不能被 UI 写成“已读/已到达”。
14. 收件箱只包含签名有效的自建应用内部消息；外部客户微信会话不能被错误表示为已同步。
15. 测试回调 XML 外部实体注入、消息重复、过长内容、越权读取和未授权回复；接收内容的清理策略按 90 天默认值生效。
16. 完成生产 HTTPS 反向代理、回调域名白名单、企业微信真实授权及至少一轮接收/发送实机验收，再标为“已联调”。
