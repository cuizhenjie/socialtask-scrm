## 最小企业微信 PoC 实施顺序（授权后）

1. 在企业微信管理后台创建或核对自建应用，确认应用可见范围包含测试内部成员；记录 CorpID、AgentId、Secret，严禁提交仓库。
2. 部署 API 和 H5 至可访问的已备案/获准 HTTPS 域名；设置 `APP_PUBLIC_URL`；反向代理 `/api/v1/wecom/callback` 直接转 Spring Boot 8080，不经过 Next `/api/proxy`。
3. 配置 Callback Token / EncodingAESKey / CorpID，验证回调 GET 原始 `echostr`，检查 AES 签名校验失败不会入库。可用日志只记录返回码，不能打印 token、解密密文、客户消息原文。
4. 先从测试内部成员向自建应用发送纯文本，再发重复回调，检验后台会话只产生 1 条入站记录；非 text 类型仅记录占位说明。
5. 绑定成员 `wecom_userid`，管理员下发测试 SERVICE_TICKET，检查 `textcard` 接收人、标题、跳转链接、登录权限；记录实际端到端截图与时间。
6. 由工作台回复成员，验证企业微信官方 API 返回码和实际可见消息。平台 `errcode=0` 只证明 API 接受，不代表已读。
7. 关闭 `WECOM_ENABLED` 重试消息，检查状态为 `NOT_CONFIGURED`；发出无效 UserID 时验证失败、手动重试、提醒归档。
8. 经合法业务授权后，单独评估微信客服或会话存档相关官方接口能否用于客户服务信息聚合。未获许可时，不得读取、同步成员的外部私聊。

## 工单 SLA 真实验收顺序

1. 备份 MySQL 数据；在测试库分别执行 Flyway V1/V2/V3 并观察实际执行 SQL、索引、外键、旧任务/客户回填状态。
2. 管理端创建 `SERVICE_TICKET + HIGH`，首次响应 SLA 30 分钟、解决 SLA 240 分钟（工作日 09:00–18:00）；确认跨周末计算结果与系统时区一致。
3. 让执行人提交处理结果；首次响应时间写入 `task_sla`，退回后保留最早响应时间；管理员审核通过后写入解决时间。
4. 未响应或未解决的工单进入预警区间，检查唯一预警、唯一违约记录、消息收件箱提醒和统计值一致。
5. 把人员停用、工单转派给客服/官方助理，核对操作日志、SLA 历史不被重置；服务工单不能转派给素人。
6. 以管理员/执行人分别访问 SLA 策略、客户分类、统计和内部会话，确认非管理员返回 403，截图和客户信息遵守最小权限。
7. 核对客户分类增删/组合筛选、工单组/标签筛选、报表趋势以及原有客户身份去重；根据实际数据规模做索引和慢查询检测。
